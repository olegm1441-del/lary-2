# LARI DOCX style guide

Дата: 28 июля 2026.

Этот файл фиксирует общий визуальный и содержательный контракт рабочих DOCX LARI. Он применяется к новым специализированным генераторам и постепенно заменяет legacy-рендереры без изменения пользовательских сценариев.

## Страница и типографика

- Формат: A4; landscape допустим для широких операционных таблиц.
- Поля: 20 мм со всех сторон.
- Основной шрифт: Arial, 11 pt.
- Межстрочный интервал: 1,15.
- Интервал после абзаца: 6 pt.
- Заголовок документа: 20 pt, полужирный.
- Заголовок раздела: 14–15 pt, полужирный, синий фирменный акцент.
- Текст таблиц: 9–10 pt; содержимое не должно требовать горизонтальной прокрутки после открытия в Word.
- Номер страницы: в центре нижнего колонтитула.

## Структура

1. Один содержательный заголовок документа.
2. Краткая таблица исходных параметров.
3. Смысловые разделы в порядке пользовательской задачи.
4. Таблицы для повторяющихся структур: источников, таймингов, подготовки, логистики.
5. Прямые кликабельные ссылки, если документ использует внешние источники.

## Правила текста

- В документ попадает готовый рабочий материал, а не инструкция по использованию интерфейса.
- Не выводятся Markdown, JSON, prompt, внутренние поля, статусы API, debug warnings и служебные названия.
- Не добавляются неподтверждённые числа, география, организации, даты и ссылки.
- Сырой пользовательский текст можно использовать как входные данные, но разговорные формулировки проходят нормализацию перед выводом.
- Не добавляются универсальные блоки «Что проверить вручную», если проверка уже выражена предметным разделом.

## Применение в текущем патче

- `social-research`: таблица исходных параметров, доказательств с кликабельными URL, готовый вопрос для опроса во ВКонтакте и таблица полезных материалов.
- `scenario-plan`: таблица параметров, отдельная таблица таймингов для каждого дня, таблицы подготовки и логистики.

Остальные legacy DOCX-генераторы мигрируют на этот контракт отдельными точечными задачами.
