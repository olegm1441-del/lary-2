# Архитектура Лари 2 / MVP 0.1

Лари 2 — модульная веб-платформа для подготовки, анализа и проверки заявок ПФКИ. Внешне продукт называется Лари 2, внутри команды текущая версия считается MVP 0.1.

## 1. Главный принцип

Лари 2 — не чат с нейросетью, а пошаговый мастер заявки. Пользователь создает проект, отвечает на простые вопросы, выбирает модуль и получает результат: черновик текста, проверку, список рисков, письмо поддержки или аналитический вывод.

## 2. Целевая аудитория

Основная аудитория — женщины и ЛПР в сфере культуры 45–65+. Интерфейс должен быть крупным, простым и пошаговым: один экран — одно действие, короткие поля, примеры, автосохранение, понятные статусы.

## 3. Слои системы

Frontend:
- Next.js;
- Tailwind CSS;
- shadcn/ui;
- карточки модулей;
- пошаговые формы;
- личный кабинет.

Backend:
- FastAPI;
- routers для API;
- services для AI, базы, речи и контекста;
- schemas для валидации;
- GigaChat как основной AI-провайдер.

Database:
- PostgreSQL на Railway;
- хранит пользователей, проекты, ответы, запуски модулей, результаты, оплату, промокоды и аналитику.

Deploy:
- Railway project;
- service `web`;
- service `api`;
- service `Postgres`.

## 4. AI-слой

Все AI-запросы идут через backend. Frontend никогда не получает ключи GigaChat или SaluteSpeech.

Поток:
1. Пользователь вводит данные.
2. Frontend отправляет данные в API.
3. API собирает контекст проекта.
4. API выбирает промпт модуля.
5. API обращается к GigaChat.
6. API сохраняет вход, выход, статус и ошибки.
7. Frontend показывает результат.

## 5. Речь

SaluteSpeech подключается отдельным сервисным слоем. Голосовой ввод не заменяет модули, а помогает заполнять поля: речь переводится в текст, текст попадает в форму, затем обычный модуль обрабатывает его через GigaChat.

## 6. Длинный контекст

Для длинных заявок и материалов система не должна отправлять один хаотичный огромный промпт. Контекст собирается через context builder:
- паспорт проекта;
- нужный раздел заявки;
- ответы пользователя;
- правила модуля;
- ограничения по длине;
- предыдущие результаты;
- доказательства и источники.

В будущем большие тексты будут обрабатываться чанками: сначала анализ частей, потом общий вывод.

## 7. Railway

В Railway должно быть три сервиса:
- Postgres;
- api с root directory `apps/api`;
- web с root directory `apps/web`.

DATABASE_URL берется из Postgres. GIGACHAT_CREDENTIALS и SALUTE_SPEECH_AUTHORIZATION_KEY хранятся только в Railway Variables.
